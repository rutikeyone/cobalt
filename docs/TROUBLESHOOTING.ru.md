# Частые ошибки

Каждая ошибка, которую Cobalt бросает во время работы, заканчивается ссылкой на свой пункт на этой
странице. В пункте сказано, когда ошибка возникает и что с ней делать.

## Чтение из графа

### CobaltNotRegisteredError

```
Config is not registered in scope "app" or its ancestors. Resolving: Api -> Repository -> Config.
Nothing in this scope tree registers Config. Register it, or if it is a @cobaltInject class, run
build_runner again.
```

Кто-то запросил тип, который не регистрирует ни один скоуп отсюда до корня.

- С генератором: поставьте на класс `@cobaltInject` и снова запустите `dart run build_runner build`.
  Если тип регистрируется руками, вне сгенерированного контейнера, перечислите его в
  `@CobaltScopeRoot(provides: [...])`.
- Без генератора: зарегистрируйте его в `build()` этого скоупа или скоупа выше.
- `Resolving:` показывает, кто просил, от первого к последнему. Начинайте с первого имени.
- После цепочки идет подсказка. Если ключ регистрируют скоупы ниже или сбоку от этого, сообщение
  называет до трех из них: поиск идет вверх, а не вниз, так что перенесите регистрацию выше или
  запрашивайте из того скоупа. Если тип зарегистрирован под другими именами, оно перечисляет эти
  ключи, например `Api, Api(fake)`: проверьте `name:`. Если ни то ни другое, оно говорит, что ключ
  не регистрирует никто во всем дереве скоупов: см. первые два пункта. Те же сведения ошибка несет
  в полях `registeredElsewhere` и `sameType`.
- Если в сообщении сказано, что скоуп ещё строится: eager `registerSingleton` запросил зависимости
  раньше, чем их зарегистрировали ниже в `build()`. Перенесите его под них или сделайте ленивым.
- Скоуп видит только себя и скоупы выше. Тип, зарегистрированный в скоупе сессии или экрана, из
  корня не виден.

### CobaltNotReadyError

Асинхронную регистрацию — `registerAsyncSingleton` или класс с `@CobaltInit` — прочитали до того,
как `init()` её построил.

- Дождитесь старта: `await CobaltApplication.start(...)` или `await $startCobalt()`. Во Flutter
  `CobaltAppScope` показывает `loading`, пока граф не готов, поэтому читайте внутри приложения, а не
  до `runApp`.
- Для скоупа, который вы создали сами, выполните `await child.init()` до чтения из него.

### CobaltLazyAsyncError

Ленивую асинхронную регистрацию — `registerLazyAsyncSingleton` или ленивый класс с `@CobaltInit` —
прочитали через `get` до того, как её кто-то построил.

- Используйте `await scope.getAsync<T>()`. Первый вызов строит объект, следующие получают тот же. В
  виджете ожидание берёт на себя `CobaltAsyncBuilder`.
- Если объект должен быть готов к открытию экрана, запустите его заранее через `warmUp`.

### CobaltAsyncTransientError

`get` у асинхронного транзиента — `registerAsyncFactory` или `@cobaltTransient` на классе с
`@CobaltInit`. Он строится заново при каждом вызове, поэтому каждый вызов надо ждать.

- Используйте `await scope.getAsync<T>()` или `getAllAsync` для списка. Правило линтера
  `cobalt_async_transient_read_synchronously` показывает это место в редакторе.

### CobaltParamRequiredError

Регистрация принимает значение с места вызова — `registerParamFactory` или класс с `@CobaltParam`, —
а её прочитали без него.

- Используйте `scope.getWithParam<T, P>(value)` или `getAsyncWithParam`, если объект строится
  асинхронно. В виджете — `context.cobaltWithParam<T, P>(value)`.

### CobaltNotParameterizedError

Обратный случай: `getWithParam` у регистрации, которая параметр не принимает.

- Используйте `get<T>()`.

### CobaltAsyncParamError

`getWithParam` у регистрации, которая строится из параметра асинхронно (`registerAsyncParamFactory`).

- Используйте `await scope.getAsyncWithParam<T, P>(value)`.

### CobaltParamTypeError

В `getWithParam` передали значение не того типа, который принимает регистрация. Обычно это запись,
у которой поля называются иначе или идут в другом порядке.

- Передавайте ровно объявленный тип. С генератором собирайте сгенерированную запись `$<Class>Args`.

### CobaltCycleError

```
Dependency cycle detected: Session -> Api -> Session
```

Регистрации из списка нужны друг другу, поэтому ни одну нельзя построить первой.

- Разорвите цикл: вынесите то, что нужно обеим сторонам, в третий класс, или пусть одна сторона
  получает другую в момент использования, а не в конструкторе.
- С генератором сборка падает на цикле, а правило линтера `cobalt_dependency_cycle` показывает его в
  редакторе.

## Регистрация

### CobaltDuplicateRegistrationError

Один и тот же тип с одним и тем же именем зарегистрирован в скоупе дважды.

- Уберите одну из регистраций.
- Чтобы держать несколько реализаций одного типа, дайте каждой имя — `name: 'audit'` при регистрации,
  `get<Logger>(name: 'audit')` при чтении — и читайте все сразу через `getAll<T>()`.
- Чтобы заменить регистрацию в тесте или во flavor, используйте override, а не вторую регистрацию.

### CobaltScopeStateError

Скоуп в неподходящем состоянии для этого вызова. В сообщении сказано, в каком, и что просили:

- **Асинхронная регистрация после старта `init()`.** `init()` забирает асинхронные регистрации,
  которые нашёл при старте, и выполняется один раз. Регистрируйте их до `init()`. Чтобы добавить
  позже, создайте дочерний скоуп, зарегистрируйте там и выполните `await child.init()`.
- **Скоуп используют после `dispose()`** или во время него. Кто-то сохранил ссылку на старый скоуп —
  часто это сессия, из которой уже вышли. Читайте из текущего скоупа.

### CobaltDependsOnError

`dependsOn` называет то, что `init()` не строит: тип, который никто не регистрирует, обычную
регистрацию, ленивую или асинхронную фабрику. `dependsOn` лишь задаёт порядок асинхронных синглтонов
в `init()`, так что ждать тут нечего.

- Если тип никто не регистрирует, зарегистрируйте его — как в
  [CobaltNotRegisteredError](#cobaltnotregisterederror).
- Иначе уберите его из `dependsOn`. Обычная зависимость разрешается, когда нужна, ленивая — первым
  `getAsync`, асинхронная фабрика — каждым `getAsync`.

### CobaltOverrideError

Override ничего не заменил.

- **Нет аргумента типа.** `CobaltOverride.value(FakeClock())` заменяет `FakeClock`, а внутри
  списка — `Object`. Назовите зарегистрированный тип: `CobaltOverride<Clock>.value(FakeClock())`.
  Это ловит правило линтера `cobalt_override_needs_type_argument`.
- **Не тот скоуп.** Тип зарегистрирован в другом скоупе, сообщение его называет. Поставьте override
  туда — тогда его увидят и фабрики, которые этот тип используют.

### CobaltDecoratorError

Декоратор добавлен слишком поздно или ничего не оборачивает.

- **Слишком поздно:** объект уже выдали, и тот, кто его держит, остался бы с необёрнутым. Добавляйте
  декораторы в том же `build()`, что и регистрацию, до того как её кто-то разрешит.
- **Ничего не оборачивает:** этот скоуп такой ключ не регистрирует. Если регистрирует другой,
  сообщение его называет — декорируйте там.

### CobaltHookError

`hookAll` вызвали после того, как скоуп или скоуп ниже уже построил объекты. Через хук они бы не
прошли.

- Добавляйте хуки первыми, там, где собирается скоуп, до любого `get` и eager-регистрации. Правило
  линтера `cobalt_hook_added_too_late` ловит это в пределах одного блока.

## Старт и остановка

### CobaltBootstrapError

Шаг бутстрапа — `@CobaltBootstrap` или `CobaltBootstrapStep` — бросил исключение. Сообщение называет
шаг и содержит исходную ошибку; `cause` и `causeStackTrace` хранят её.

- Исправьте исходную ошибку. Во Flutter `CobaltAppScope` показывает `errorBuilder` с кнопкой повтора.

### CobaltInitTimeoutError

Старт не уложился в `init(timeout:)` или `initTimeout:`. Сообщение перечисляет всё, что ещё не
построено.

- Выясните, почему они медленные. Обычная причина — сетевой запрос без собственного таймаута.
- То, что не нужно первому экрану, можно убрать со старта: сделайте его ленивым
  (`registerLazyAsyncSingleton`) и стройте при первом обращении.
- Или увеличьте таймаут.

### CobaltWarmUpError

`warmUp` не смог построить часть регистраций. Сообщение перечисляет каждую с её ошибкой. Остальные
построены, а следующий `getAsync` упавшей попробует снова.

- Исправьте перечисленные ошибки — это те же ошибки, которые бросил бы `getAsync`.

### CobaltDisposeError

Скоуп закрыт, но часть объектов закрылась с ошибкой: `dispose()` бросил исключение или не уложился в
срок. Сообщение перечисляет все сбои; `hasTimeout` отличает таймауты от ошибок.

- Исправьте `dispose()`, который упал. Всё остальное всё равно закрыто.
- При таймауте ускорьте медленный `dispose()` или дайте закрытию больше времени:
  `scope.dispose(timeout: ...)`. По умолчанию — 30 секунд на всё дерево.

## Во Flutter

### CobaltNoScopeError

`context.cobalt<T>()` не нашёл скоуп над виджетом.

- Поставьте `CobaltAppScope` в `MaterialApp.builder`, как в быстром старте README, или оберните
  поддерево в `CobaltScopeWidget`.
- Маршрут, открытый через `Navigator.push`, строит навигатор — выше экрана, который его открыл, —
  поэтому он не видит скоуп этого экрана. Передайте скоуп новому экрану или поставьте скоуп выше
  навигатора.

### CobaltNoAppScopeError

`CobaltAppScope.of(context)` — он нужен для `restart()` — не нашёл `CobaltAppScope` над виджетом.

- Запускайте приложение через `CobaltAppScope` или `CobaltAppScope.builder`. `CobaltScopeProvider`
  лишь публикует скоуп, которым владеет кто-то другой, поэтому перезапустить его не может.

## Когда падает `build_runner`

Генератор останавливает сборку сообщением, в котором сказано, что поменять. Обычные случаи:

- **Зависимость, которую никто не регистрирует.** Исправляется так же, как
  [CobaltNotRegisteredError](#cobaltnotregisterederror): поставьте аннотацию на класс или перечислите
  его в `@CobaltScopeRoot(provides: [...])`. Сообщение перечисляет все пробелы сразу.
- **`requires int` у параметра со значением по умолчанию.** Значение по умолчанию работает, только
  если генератор может параметр опустить: именованный или позиционный в конце. Перед внедряемым
  позиционным его пропустить нельзя, и сообщение об этом говорит; сделайте параметр именованным.
- **Два класса с `@CobaltScopeRoot` в одном пакете.** У пакета один сгенерированный корень. Оставьте
  один.
- **Цикл зависимостей.** См. [CobaltCycleError](#cobaltcycleerror).
- **Абстрактный класс с `@CobaltInject`.** Генератор не может его построить. Аннотируйте конкретный
  класс и выставьте его под интерфейсом: `@CobaltInject(exposeAs: ApiClient)`.
- **Обобщенный класс с `@CobaltInject`.** Сообщение говорит, что класс объявляет параметры типа и
  единственной инстанциации для регистрации нет. Назовите те, что он регистрирует, выписав каждый
  аргумент типа: `@CobaltInject(instantiations: [Cache<Note>, Cache<User>])`. Голый `Cache` в списке
  читается как `Cache<dynamic>` и отвергается, как и `exposeAs` рядом с `instantiations`.
- **Поля `@injected` у обобщенного класса не компилируются.** Класс подмешивает миксин со своими
  параметрами типа: `class Cache<T> with _$Cache<T>`. Голый `with _$Cache` их теряет.

Как устроена проверка — в [GUIDE_CODEGEN.ru.md](../GUIDE_CODEGEN.ru.md#5-граф-обязан-быть-полным), а
[плагин линтера](../GUIDE_CODEGEN.ru.md#16-плагин-линтера) показывает большинство этих ошибок в
редакторе ещё до сборки.

## Первая сборка

Что показывает новое приложение по ходу [быстрого старта](../README.ru.md#быстрый-старт):

- **`Target of URI hasn't been generated: 'cobalt.g.dart'`, и `$CobaltRootScope` не класс.**
  Генератор еще не запускался. Выполните `dart run build_runner build` и повторяйте после каждой
  правки аннотаций; `dart run build_runner watch` держит файл актуальным, пока вы работаете.
- **`The name 'MyApp' isn't a class` в `test/widget_test.dart`.** Этот тест пришел с
  `flutter create` и проверяет приложение-счетчик, которое вы заменили. Удалите его; тест для нового
  приложения есть в [`examples/hello/test`](../examples/hello/test).
- **`The imported package 'cobalt' isn't a dependency` в `lib/cobalt.g.dart`.** Сгенерированный код
  импортирует рантайм напрямую, поэтому приложение должно от него зависеть: `flutter pub add cobalt`.
